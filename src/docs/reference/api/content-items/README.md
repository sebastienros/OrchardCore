# Content item management API (`OrchardCore.Contents`)

The content item management API lists, reads, creates, updates, validates, renders, publishes,
unpublishes, and deletes content items. Enable the **Contents** feature
(`OrchardCore.Contents`). The feature advertises the Remote Management capability
`content-items`.

## Authentication and authorization

Every endpoint uses Orchard Core's `Api` authentication scheme, requires both
`AccessRemoteManagement` and `AccessContentApi`, and disables antiforgery validation. See
[Remote Management authentication](../../modules/RemoteManagement/README.md) for API
credential configuration.

Resource permissions are evaluated in addition to those two permissions:

| Operation | Additional permission |
| --- | --- |
| List | `ListContent`, evaluated per content type |
| Get or render a published version | `ViewContent` on the item |
| Get or render a draft/latest unpublished version | `PreviewContent` on the item |
| Create or update a draft; validate; create a draft version | `EditContent` on the item |
| Create/update and publish; publish or unpublish | `EditContent` and/or `PublishContent` as described by the operation |
| Delete | `DeleteContent` on the item |
| Get schema | At least one of `ListContent`, `EditContent`, or `ViewContent` for the type |

Orchard Core's normal ownership and content-type permission rules apply when these permissions
are evaluated. Listing omits content types for which the caller lacks `ListContent` rather than
returning `403`.

Unauthenticated requests return `401 Unauthorized`. Any required permission failure returns
`403 Forbidden` Problem Details:

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.4",
  "title": "Forbidden",
  "status": 403,
  "detail": "You do not have sufficient permissions to complete this request"
}
```

## Base route

`/api/content`

All request and response bodies use `application/json`.

### Common headers

| Header | Required | Value |
| --- | --- | --- |
| `Authorization` | Yes | Credentials for the configured `Api` scheme, for example `Bearer <token>`. |
| `Content-Type` | For requests with a body | `application/json` |
| `Accept` | No | `application/json` |

## Endpoints

| Method | Path | Purpose |
| --- | --- | --- |
| `GET` | `/api/content` | List content items |
| `GET` | `/api/content/{contentItemId}` | Get one version |
| `POST` | `/api/content` | Create or update and optionally publish |
| `POST` | `/api/content/draft` | Create a new draft |
| `PUT` | `/api/content/{contentItemId}` | Update and publish |
| `PUT` | `/api/content/{contentItemId}/draft` | Update and keep as draft |
| `POST` | `/api/content/{contentItemId}/draft` | Create or refresh a draft version |
| `POST` | `/api/content/{contentItemId}/publish` | Publish the draft |
| `POST` | `/api/content/{contentItemId}/unpublish` | Unpublish the published version |
| `DELETE` | `/api/content/{contentItemId}` | Delete the latest version |
| `POST` | `/api/content/validate` | Validate a create/existing draft payload |
| `POST` | `/api/content/{contentItemId}/validate` | Validate an update |
| `GET` | `/api/content/{contentItemId}/render` | Render a version |
| `GET` | `/api/content/schema/{contentType}` | Get the type's JSON Schema |

## Shared contracts

### Content item JSON

Content item documents use the following exact, Pascal-cased well-known property names:

| Property | Type | Notes |
| --- | --- | --- |
| `ContentItemId` | string or null | Logical identifier shared by all versions. Omit for a new item. |
| `ContentItemVersionId` | string or null | Version identifier; generated by the content manager. |
| `ContentType` | string or null | Required when creating; must name an existing content type. It cannot be changed by an update. |
| `DisplayText` | string or null | Display text. |
| `Latest` | boolean | Version-state value. |
| `Published` | boolean | Version-state value. |
| `ModifiedUtc` | string(date-time) or null | Version update time. |
| `PublishedUtc` | string(date-time) or null | Publication time. |
| `CreatedUtc` | string(date-time) or null | Creation/first-publication time. |
| `Owner` | string or null | Creator user ID. |
| `Author` | string or null | Last modifier's user name. |
| `<part name>` | object | Content-type-specific part data. |

The remaining top-level members and all nested part/field members depend on the content
definition and enabled modules. Use the schema endpoint for the current contract. The schema
marks IDs, state flags, and timestamps as read-only and requires `ContentType`; it permits
additional properties.

Representative `Article` document:

```json
{
  "ContentItemId": "4xyz6d8qk2s9r1n7m5p3t0vabc",
  "ContentItemVersionId": "4xyz6d8qk2s9r1n7m5p3t0vabd",
  "ContentType": "Article",
  "DisplayText": "API reference",
  "Latest": true,
  "Published": true,
  "ModifiedUtc": "2026-08-29T01:25:00Z",
  "PublishedUtc": "2026-08-29T01:25:00Z",
  "CreatedUtc": "2026-08-29T01:20:00Z",
  "Owner": "4abc",
  "Author": "admin",
  "TitlePart": {
    "Title": "API reference"
  }
}
```

### Version selection

Endpoints with a `version` query parameter accept:

| Value | Selection |
| --- | --- |
| `published` | Published version; this is the default. |
| `draft` | A required draft version. |
| `latest` | Latest version, published or draft. |

Matching is case-insensitive. Any other value follows the default and selects the published
version; it is not a validation error.

### Problem and validation responses

A missing item, content type, required draft, or unusable create/update target returns
`404 Not Found`:

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.5",
  "title": "Not Found",
  "status": 404
}
```

A save-time content handler validation failure returns `400 Bad Request` validation Problem
Details. Keys and messages are contributed by the content type's validators and are therefore
schema dependent:

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.1",
  "title": "One or more validation errors occurred.",
  "status": 400,
  "detail": "The Title field is required.",
  "errors": {
    "TitlePart.Title": [
      "The Title field is required."
    ]
  }
}
```

Malformed JSON or a missing required JSON body also returns `400`. The explicit missing-body
response for save operations has title `Bad request` and detail
`A content item payload is required.`. The API does not use `409 Conflict`.

## Operations

### List content items

`GET /api/content`

| Query parameter | Type | Default | Behavior |
| --- | --- | --- | --- |
| `contentType` | string | none | Limits the query to one type. An unknown type produces an empty page. |
| `status` | string | `published` | `published`, `draft`, or `latest`; any other value selects published. |
| `skip` | integer | `0` | Values below `0` are normalized to `0`. |
| `take` | integer | `20` | Clamped to the inclusive range `1` through `100`. |

```bash
curl -H "Authorization: Bearer $TOKEN" \
  "https://localhost:5001/api/content?contentType=Article&status=published&skip=0&take=20"
```

`200 OK` returns the total before paging and content items ordered by `ModifiedUtc` descending:

```json
{
  "skip": 0,
  "take": 20,
  "totalCount": 1,
  "items": [
    {
      "ContentItemId": "4xyz6d8qk2s9r1n7m5p3t0vabc",
      "ContentItemVersionId": "4xyz6d8qk2s9r1n7m5p3t0vabd",
      "ContentType": "Article",
      "DisplayText": "API reference",
      "Latest": true,
      "Published": true,
      "ModifiedUtc": "2026-08-29T01:25:00Z",
      "PublishedUtc": "2026-08-29T01:25:00Z",
      "CreatedUtc": "2026-08-29T01:20:00Z",
      "Owner": "4abc",
      "Author": "admin",
      "TitlePart": {
        "Title": "API reference"
      }
    }
  ]
}
```

Also returns `401` or `403`.

### Create or update a content item

`POST /api/content`

| Parameter | Location | Type | Required | Default |
| --- | --- | --- | --- | --- |
| `draft` | query | boolean | No | `false` |
| body | body | content item | Yes | — |

With no body `ContentItemId`, this creates an item. An ID that resolves to an existing item updates
its required current draft for backward compatibility. An unknown body ID still enters the create
path, and Orchard Core assigns a new generated ID. `draft=false` publishes after saving and
requires `EditContent` plus `PublishContent`; `draft=true` keeps a draft and requires `EditContent`.

```bash
curl -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "ContentType": "Article",
    "DisplayText": "API reference",
    "TitlePart": {
      "Title": "API reference"
    }
  }' \
  "https://localhost:5001/api/content?draft=false"
```

`200 OK` returns the complete created or updated document:

```json
{
  "ContentItemId": "4xyz6d8qk2s9r1n7m5p3t0vabc",
  "ContentItemVersionId": "4xyz6d8qk2s9r1n7m5p3t0vabd",
  "ContentType": "Article",
  "DisplayText": "API reference",
  "Latest": true,
  "Published": true,
  "ModifiedUtc": "2026-08-29T01:25:00Z",
  "PublishedUtc": "2026-08-29T01:25:00Z",
  "CreatedUtc": "2026-08-29T01:20:00Z",
  "Owner": "4abc",
  "Author": "admin",
  "TitlePart": {
    "Title": "API reference"
  }
}
```

Also returns `400`, `401`, `403`, or `404`.

### Create a draft content item

`POST /api/content/draft`

The required body is a content item whose `ContentType` exists. Omit `ContentItemId` to create a
draft. An unknown supplied ID also creates a draft with a new generated ID; an ID that resolves to
an existing item is rejected by this create-only operation. Requires `EditContent`.

```bash
curl -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "ContentType": "Article",
    "DisplayText": "Draft article",
    "TitlePart": {
      "Title": "Draft article"
    }
  }' \
  https://localhost:5001/api/content/draft
```

`201 Created` returns the draft and sets `Location` to `/api/content/{ContentItemId}`:

```json
{
  "ContentItemId": "4xyz6d8qk2s9r1n7m5p3t0vabc",
  "ContentItemVersionId": "4xyz6d8qk2s9r1n7m5p3t0vabd",
  "ContentType": "Article",
  "DisplayText": "Draft article",
  "Latest": true,
  "Published": false,
  "ModifiedUtc": "2026-08-29T01:25:00Z",
  "PublishedUtc": null,
  "CreatedUtc": "2026-08-29T01:20:00Z",
  "Owner": "4abc",
  "Author": "admin",
  "TitlePart": {
    "Title": "Draft article"
  }
}
```

If the ID identifies an existing item, creation is not allowed and returns `404`. Also returns
`400`, `401`, or `403`.

### Update and publish a content item

`PUT /api/content/{contentItemId}`

`contentItemId` is a required string path parameter. The required content item body is merged
into the required draft; arrays are replaced rather than concatenated. The route ID identifies
the item. A nonblank `ContentType` must match its existing type. Requires `EditContent` and
`PublishContent`.

```bash
curl -X PUT -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "ContentType": "Article",
    "DisplayText": "Updated article",
    "TitlePart": {
      "Title": "Updated article"
    }
  }' \
  https://localhost:5001/api/content/4xyz6d8qk2s9r1n7m5p3t0vabc
```

`200 OK` returns the published content item:

```json
{
  "ContentItemId": "4xyz6d8qk2s9r1n7m5p3t0vabc",
  "ContentItemVersionId": "4xyz6d8qk2s9r1n7m5p3t0vabd",
  "ContentType": "Article",
  "DisplayText": "Updated article",
  "Latest": true,
  "Published": true,
  "ModifiedUtc": "2026-08-29T01:30:00Z",
  "PublishedUtc": "2026-08-29T01:30:00Z",
  "CreatedUtc": "2026-08-29T01:20:00Z",
  "Owner": "4abc",
  "Author": "admin",
  "TitlePart": {
    "Title": "Updated article"
  }
}
```

Changing `ContentType` produces a `400` validation error with key `ContentType` and message
`The content type cannot be changed.`. Also returns `401`, `403`, or `404`.

### Validate a content item payload

`POST /api/content/validate`

The content item body is required. If it includes `ContentItemId`, the API validates an update
to that required draft; otherwise `ContentType` must identify an existing type and the API
validates a new item. Requires `EditContent`. Validation invokes content handlers but cancels
the YesSql session, so it does not persist the merged item.

```bash
curl -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "ContentType": "Article",
    "TitlePart": {
      "Title": ""
    }
  }' \
  https://localhost:5001/api/content/validate
```

`200 OK` reports validation in the response rather than using status `400`:

```json
{
  "isValid": false,
  "errors": {
    "TitlePart.Title": [
      "The Title field is required."
    ]
  }
}
```

Error keys/messages are content-type dependent. Also returns `401`, `403`, or `404`.

### Validate a content item update

`POST /api/content/{contentItemId}/validate`

`contentItemId` and the content item body are required. The API merges the body into the
required draft, validates it without saving, and requires `EditContent`.

```bash
curl -X POST -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "ContentType": "Article",
    "TitlePart": {
      "Title": "Valid title"
    }
  }' \
  https://localhost:5001/api/content/4xyz6d8qk2s9r1n7m5p3t0vabc/validate
```

`200 OK` returns:

```json
{
  "isValid": true,
  "errors": {}
}
```

Also returns `401`, `403`, or `404`.

### Render a content item

`GET /api/content/{contentItemId}/render`

| Parameter | Location | Type | Required | Default |
| --- | --- | --- | --- | --- |
| `contentItemId` | path | string | Yes | — |
| `version` | query | string | No | `published` |
| `displayType` | query | string | No | `Detail` |

`displayType` is passed to display management; available display types and resulting markup
depend on the content type, placement, theme, and enabled features. Requires `ViewContent` for
a published item or `PreviewContent` otherwise.

```bash
curl -H "Authorization: Bearer $TOKEN" \
  "https://localhost:5001/api/content/4xyz6d8qk2s9r1n7m5p3t0vabc/render?version=published&displayType=Detail"
```

`200 OK` returns:

```json
{
  "contentItemId": "4xyz6d8qk2s9r1n7m5p3t0vabc",
  "displayType": "Detail",
  "html": "<article><h1>API reference</h1></article>"
}
```

The `html` value is dynamic. Also returns `401`, `403`, or `404`.

### Get a content item JSON Schema

`GET /api/content/schema/{contentType}`

`contentType` is a required string path parameter. No body or query parameters. The caller
must have at least one of `ListContent`, `EditContent`, or `ViewContent` for that type.

```bash
curl -H "Authorization: Bearer $TOKEN" \
  https://localhost:5001/api/content/schema/Article
```

`200 OK` returns a JSON Schema Draft 2020-12 document generated from the current content
definition and registered CLR part/field types:

```json
{
  "contentType": "Article",
  "schema": {
    "$schema": "https://json-schema.org/draft/2020-12/schema",
    "title": "Article",
    "type": "object",
    "properties": {
      "ContentItemId": {
        "type": ["string", "null"],
        "readOnly": true
      },
      "ContentType": {
        "type": ["string", "null"],
        "const": "Article"
      },
      "DisplayText": {
        "type": ["string", "null"]
      },
      "TitlePart": {
        "type": "object",
        "properties": {
          "Title": {
            "type": ["string", "null"]
          }
        }
      }
    },
    "required": ["ContentType"],
    "additionalProperties": true
  }
}
```

The complete `properties`, descriptions, defaults, and references are schema dependent.
Also returns `401`, `403`, or `404`.
