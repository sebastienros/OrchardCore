# Deployment (`OrchardCore.Deployment`)

The Deployment module provides a way to build, export, and import packages that move content and configuration between Orchard Core sites. A deployment package contains a `Recipe.json` file and can contain additional files required by its recipe steps.

Deployment packages use the same recipe infrastructure as setup recipes. See [Recipes](../Recipes/README.md) for information about recipe execution and the recipe steps contributed by other features.

## Deployment plans

A deployment plan is an ordered list of deployment steps. Each step contributes recipe steps or files to the generated package. The available steps depend on the features enabled for the tenant. For example, the Contents, Media, and Queries features contribute steps for exporting their own data.

To create and execute a plan:

1. In the admin, go to **Tools** > **Deployments** > **Plans**.
2. Select **Add Deployment Plan**, enter a name, and save the plan.
3. Open the plan and select **Add Step**.
4. Configure each step and arrange the steps in the order in which they should be added to the package.
5. Select **Execute**, then select **File Download** to generate and download a `.zip` package.

The Deployment module provides these general-purpose steps:

| Step | Purpose |
|------|---------|
| Custom File | Adds a text file at a specified path in the package. |
| JSON Recipe | Adds recipe-step JSON directly to `Recipe.json`. |
| Recipe File | Sets the recipe metadata, such as its name, version, categories, and whether it is a setup recipe. |
| Deployment Plans | Exports deployment plan definitions so they can be recreated on another site. |

!!! note
    A deployment step is available only when the feature that provides it is enabled. If an imported plan contains an unknown step type, enable the related feature before importing the plan again.

## Import a package

In the admin, go to **Tools** > **Deployments** and use one of these options:

- **Package Import** accepts a `.zip` deployment package or a `.json` recipe file.
- **JSON Import** accepts recipe JSON entered directly in the editor.

Local package uploads and JSON imports use `DeploymentPackageService` to stage and
validate input before executing it. ZIP uploads require a root `Recipe.json` with
an array of named recipe steps. Absolute/traversal paths, symlinks and duplicate
normalized archive paths are rejected. Staged files are removed when import ends.
The upload action continues to run the file-creation event pipeline before staging.

Hosts can configure `DeploymentPackageOptions` through the options system. Defaults
are 100 MiB input, 500 MiB expanded data, and 10,000 archive entries; all limits must
be positive. Byte limits are enforced while copying streams. These checks do not
make recipe execution transactional or guarantee that each recipe step succeeds.

Importing a package executes its recipe immediately. The steps run in the order in which they appear in `Recipe.json`.

!!! warning
    Import only packages and JSON from trusted sources. Recipe steps can change site configuration, features, content definitions, and content. The **Import Data** permission is security-critical and should be granted only to trusted roles.

## Create deployment plans from a recipe

The `deployment` recipe step creates or updates deployment plans. Each entry requires a plan name and a list of typed deployment steps.

```json
{
  "steps": [
    {
      "name": "deployment",
      "Plans": [
        {
          "Name": "Add a custom file",
          "Steps": [
            {
              "Type": "CustomFileDeploymentStep",
              "Step": {
                "Id": "custom-file",
                "Name": "CustomFileDeploymentStep",
                "FileName": "notes/readme.txt",
                "FileContent": "Generated by a deployment plan."
              }
            }
          ]
        }
      ]
    }
  ]
}
```

`Type` is the registered deployment step type. The properties under `Step` are specific to that type. All features that provide the referenced step types must be enabled when the recipe runs; otherwise, no plans from that recipe step are changed.

## Permissions

The module defines the following permissions:

| Permission | Purpose |
|------------|---------|
| Manage deployment plans | Create, edit, reorder, and delete plans and their steps. |
| Export Data | Execute a plan and export its package. |
| Import Data | Import and execute deployment packages or recipe JSON. |

Administrators receive these permissions by default.

## Extending deployment

A module can provide a custom deployment step by implementing an `IDeploymentSource`, deriving its step model from `DeploymentStep`, and optionally adding a display driver for its editor. Register the components together:

```csharp
services.AddDeployment<MyDeploymentSource, MyDeploymentStep, MyDeploymentStepDisplayDriver>();
```

The source processes the configured step and adds recipe steps or files to the `DeploymentPlanResult`. Register a custom execution destination by implementing `IDeploymentTargetProvider`.

`IDeploymentArchiveService.CreateAsync(plan, recipeDescriptor)` runs the registered
sources through `IDeploymentManager` and returns a readable ZIP stream. The caller
owns that stream and must dispose it; disposal removes the temporary archive.
Staged source files are removed before the stream is returned, and failed archive
creation removes its temporary files. Each export has a separate temporary path,
including simultaneous exports of plans with the same name. Authorize the caller
before invoking the service; it does not grant export permission itself.

The local download and remote multipart export actions use this shared service.
Each action supplies its existing recipe metadata and owns the returned stream
through response or request disposal.

To send packages directly to another Orchard Core site, see [Remote Deployment](../Deployment.Remote/README.md).
